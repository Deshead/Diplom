# API сервиса закупок

Базовый адрес: `http://127.0.0.1:8000/api/v1`. Все перечисленные пути используются без завершающего `/`.

API принимает `application/json`, `application/x-www-form-urlencoded` и `multipart/form-data`. Для загрузки файла нужен `multipart/form-data` с полем `file`. Вход возвращает `{"Status": true, "Token": "..."}`. Закрытые запросы требуют заголовок:

```http
Authorization: Token значение_токена
```

Ошибки валидации возвращаются с HTTP 400, отсутствие авторизации — 401/403, недостаточные права — 403, отсутствующий или чужой объект — 404. Не используйте конкретный текст сообщения об ошибке как признак успеха: проверяйте HTTP-код и содержимое ответа.

## Пользователь

| Метод и путь | Поля запроса / результат |
| --- | --- |
| `POST /user/register` | `first_name`, `last_name`, `email`, `password`; необязательные `company`, `position`, `type` (`buyer` по умолчанию или `shop`) |
| `POST /user/register/confirm` | `email`, `token` из письма |
| `POST /user/register/resend` | `email`; повторное письмо для регистрации, которая ожидает подтверждения |
| `POST /user/login` | `email`, `password`; результат `Status`, `Token` |
| `POST /user/logout` | Удаление текущего токена авторизации |
| `GET /user/details` | Профиль текущего пользователя |
| `POST /user/details` | Обновление `first_name`, `last_name`, `company`, `position`, `phone`, `password` |
| `POST /user/password_reset` | `email`; письмо с токеном восстановления |
| `POST /user/password_reset/confirm` | `token`, новый `password`; `email` можно передать для совместимости с Postman |

Регистрация не дает доступ до подтверждения email. Токен регистрации действует 24 часа, восстановления пароля — один час; использованный токен удаляется. Пароли проверяются валидаторами Django и сохраняются в виде хеша. `email` и `type` нельзя менять через редактирование профиля. После смены или восстановления пароля войдите заново: прежний токен авторизации удаляется.

Если подтверждение не пришло или истекло, вызовите `/user/register/resend`. Ответ HTTP 200 содержит `Status: true` и общее `message` для любого адреса. Письмо отправляется только неактивному пользователю с незавершенным подтверждением регистрации; отключенные администратором ранее подтвержденные аккаунты запрос не активирует. Новый токен заменяет предыдущий. Сбой почты или очереди после сохранения регистрации не вызывает HTTP 500: после восстановления сервиса можно запросить письмо повторно. Успешный HTTP-ответ сам по себе не подтверждает доставку письма.

```json
{
  "first_name": "Иван",
  "last_name": "Петров",
  "email": "ivan@example.com",
  "password": "Study-order-2026!",
  "company": "Учебный магазин",
  "position": "Менеджер"
}
```

## Каталог

Эти запросы доступны без авторизации:

| Метод и путь | Назначение |
| --- | --- |
| `GET /categories` | Список категорий |
| `GET /shops` | Магазины, принимающие заказы |
| `GET /products` | Список доступных предложений |
| `GET /products/<id>` | Одно предложение конкретного магазина |

Фильтры `/products`: `shop_id`, `category_id`, `search` (название, описание или модель). Пример: `/products?shop_id=1&category_id=224&search=iphone`.

`id` в `/products` — ID предложения `ProductInfo`, его нужно передавать в корзину. Один товар может иметь несколько предложений с разными магазинами, ценами и остатками. Ответ содержит товар, описание, магазин, модель, `quantity`, `price`, `price_rrc`, `product_parameters`. Денежные значения представлены десятичными строками, например `"65000.00"`.

## Контакты

| Метод и путь | Поля |
| --- | --- |
| `GET /user/contact` | Список адресов текущего пользователя |
| `POST /user/contact` | Обязательные `city`, `street`; `phone`, если телефон еще не заполнен. Дом и остальные части адреса необязательны |
| `PUT /user/contact` | `id` контакта и изменяемые поля |
| `DELETE /user/contact` | `items`: список ID или строка `"1,2"` |

Дополнительные поля: `first_name`, `last_name`, `middle_name`, `email`, `structure` (корпус), `building` (строение), `apartment` (квартира). Пользователь может сохранить до пяти адресов. Телефон хранится один раз в профиле: изменение `phone` через любой контакт меняет его для всех адресов. Адрес оформленного заказа хранится отдельным снимком.

```json
{
  "first_name": "Иван",
  "last_name": "Петров",
  "middle_name": "Сергеевич",
  "email": "ivan@example.com",
  "phone": "+79991234567",
  "city": "Новосибирск",
  "street": "Советская",
  "house": "10",
  "apartment": "25"
}
```

## Корзина

`GET /basket` возвращает `[]`, если корзины еще нет, либо список с одной корзиной. В ней есть `id`, `state`, `dt`, `ordered_items`, `total_sum`, `contact`.

Добавление: `POST /basket`:

```json
{"items": [{"product_info": 1, "quantity": 2}, {"product_info": 15, "quantity": 1}]}
```

Повторное добавление предложения увеличивает количество. Для изменения количества используйте ID строки корзины, полученный в `ordered_items`, и `PUT /basket`:

```json
{"items": [{"id": 1, "quantity": 3}]}
```

`quantity` — положительное целое число. Для удаления используйте `DELETE /basket`:

```json
{"items": [1, 2]}
```

Совместимость с исходным Postman: для POST/PUT поле формы `items` может быть JSON-строкой `[{"product_info":1,"quantity":2}]`, для DELETE — строкой `1,2`. Это именно ID строк при удалении и изменении, а не ID предложений каталога.

Строка корзины содержит `id`, `product_info`, `product_name`, `shop_name`, `quantity`, `price`, `total_sum`. Предложение должно быть доступно, магазин должен принимать заказы, количества должно хватать на складе. Добавление в корзину само по себе не резервирует остаток.

## Заказы

| Метод и путь | Назначение |
| --- | --- |
| `POST /order` | Оформить свою корзину: `id` корзины и `contact` своего адреса |
| `GET /order` | Свои оформленные заказы |
| `GET /order/<id>` | Подробности своего заказа |

```json
{"id": 1, "contact": 1}
```

При оформлении приложение повторно проверяет остатки, сохраняет цены и названия позиций, делает снимок адреса, уменьшает остатки и меняет состояние на `new`. Пустую или уже оформленную корзину оформить нельзя. Покупателю отправляется подтверждение, на `ADMIN_EMAIL` — накладная с составом заказа.

Заказы содержат номер `id`, дату `dt`, статус `state`, список `ordered_items`, сумму `total_sum` и контакт. Последующее редактирование адреса или импорт новых цен не меняют сохраненные данные заказа.

## Поставщик

Нужна учетная запись с `type=shop` и подтвержденным email.

| Метод и путь | Назначение |
| --- | --- |
| `POST /partner/update` | Запустить импорт: поле `file` с YAML-файлом или `url` с публичным HTTP(S)-адресом YAML |
| `GET /partner/export` | Запустить экспорт своего прайса в YAML |
| `GET /partner/jobs/<id>` | Статус и результат своей задачи |
| `GET /partner/state` | Текущий магазин: `id`, `name`, `state` |
| `POST /partner/state` | Изменить `state`: JSON boolean либо `on`/`off`, `true`/`false`, `1`/`0` |
| `GET /partner/orders` | Оформленные заказы с позициями только своего магазина |

Импорт и экспорт отвечают HTTP 202:

```json
{"Status": true, "job_id": 1}
```

Проверяйте `/partner/jobs/1`: поля `id`, `kind` (`import`/`export`), `status` (`pending`/`done`/`error`), `result`, `error`, `created_at`. При `pending` повторите запрос позже. При ошибке причина находится в `error`.

Результат успешного импорта:

```json
{"shop_id": 1, "products": 14, "categories": 4}
```

Результат успешного экспорта содержит `{"yaml": "shop: ...\n..."}`. Сохраните содержимое поля `yaml` как текст UTF-8 с расширением `.yaml`.

Пример формата прайса:

```yaml
shop: Учебный поставщик
categories:
  - id: 224
    name: Смартфоны
goods:
  - id: 1001
    category: 224
    model: sample/phone
    name: Учебный смартфон
    description: Пример товара
    price: 10000
    price_rrc: 12000
    quantity: 5
    parameters:
      Цвет: черный
      Память: 128
```

Прайс задает актуальное состояние магазина. Товар, которого больше нет в новом файле, перестает быть доступным для покупки; история заказов сохраняется. Сопоставление предложений выполняется по магазину и внешнему `id`. Название магазина берется из `shop`. Одинаковый ID категории должен иметь одинаковое название у разных магазинов; конфликт отклоняется. Размер файла ограничен 2 МиБ. Ссылка импорта должна вести на публичный ресурс; локальные и внутренние адреса не подходят.

## Администратор

| Метод и путь | Назначение |
| --- | --- |
| `GET /admin/orders` | Список всех оформленных заказов; доступ только сотруднику |
| `PATCH /admin/orders/<id>/status` | Изменить состояние: `{"state": "confirmed"}` |

Последовательность статусов: `new` → `confirmed` → `assembled` → `sent` → `delivered`. До отправки заказ можно перевести в `canceled`. Отмена возвращает остатки; `delivered` и `canceled` — конечные состояния. Повтор того же статуса не отправляет повторное письмо.

Через `/admin/` также доступны модели проекта, просмотр заказов, смена статуса и форма запуска импорта. При изменении состояния покупатель получает письмо. API администратора использует тот же заголовок `Authorization: Token ...`, что и другие закрытые endpoints.

## Источник совместимости

Пути и основные поля сохранены по [Postman-документации задания](https://documenter.getpostman.com/view/5037826/SVfJUrSc). Добавлены JSON-запросы, детали товара и заказа, экспорт, задачи и API администратора. В исходных примерах есть JSON с лишними запятыми: такие примеры нужно исправить перед отправкой, поскольку сервер ожидает корректный JSON.
