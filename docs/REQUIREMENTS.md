# Проверка требований Нетологии

Повторно сверено 24 сентября 2026 года с [заданием](https://github.com/netology-code/python-final-diplom), версия `dd11860cf2f16b890fe5031ec565482658cb7a96`. За время проверки исходное задание не изменилось.

В проекте сделана собственная реализация по текстовому описанию. Такой вариант разрешен заданием. Интерфейс покупателя в браузере не требуется: взаимодействие идет через API. Админка Django доступна отдельно.

## Базовая часть

Основание: README задания, [описание сервиса](https://github.com/netology-code/python-final-diplom/blob/master/reference/service.md), [точки входа API](https://github.com/netology-code/python-final-diplom/blob/master/reference/screens.md) и этапы 1–5.

| Требование | Реализация и проверка |
| --- | --- |
| Django REST Framework, Python 3.10 или новее | `orders/`, `backend/urls.py`; GitHub Actions запускает тесты на Python 3.10 и 3.12 |
| Магазины, категории, товары, заказы, контакты | Модели и миграции в `backend/`; создание чистой базы проверяется при каждом запуске тестов |
| URL или имя файла прайса у магазина | `Shop.url`, `Shop.filename`; источник последнего успешного импорта виден в админке |
| Категории связаны с магазинами через m2m | `Category.shops`; импорт нескольких магазинов проверяется в тестах каталога |
| Цена и остаток товара отдельно для каждого магазина | `ProductInfo`; корзина позволяет выбрать предложение нужного магазина |
| Произвольные характеристики товара | `Parameter`, `ProductParameter`; импорт и обратный экспорт сохраняют характеристики |
| Импорт предоставленного YAML | `import_catalog`, API и админка; `data/shop1.yaml` совпадает с исходным файлом, тест проверяет все 14 товаров и четыре категории |
| Регистрация и подтверждение email | `/user/register`, `/user/register/confirm`; тесты и HTTP-сценарий проверяют письмо и вход после подтверждения |
| Вход и восстановление пароля | `/user/login`, `/user/password_reset`, `/user/password_reset/confirm`; проверены истечение и однократное использование кода, отзыв старых токенов |
| Каталог, фильтрация, поиск и карточка товара | `/products`, `/products/<id>`, `/categories`, `/shops`; ответ содержит название, описание, магазин, параметры, цену и остаток |
| Добавление, изменение и удаление товаров в корзине | `/basket`; тесты проверяют операции с JSON и полем формы `items` |
| Товары разных магазинов в одном заказе | HTTP-сценарий оформляет заказ из двух магазинов и сверяет итоговую сумму |
| Один телефон и до пяти адресов | `User.phone`, `/user/contact`; тест проверяет лимит, изменение общего телефона и удаление адреса |
| Поля получателя и адреса из описания | `ContactSerializer`: имя, фамилия, отчество, email, телефон, город, улица, дом, корпус, строение, квартира |
| Подтверждение по ID корзины и контакта, статус «Новый» | `POST /order`; проверяются принадлежность адреса, остатки и переход в `new` |
| Письмо покупателю и накладная администратору | `checkout` и `send_email`; HTTP-сценарий проверяет получателей, товары, количество, сумму и адрес в письмах |
| Список, детали и статус своих заказов | `GET /order`, `GET /order/<id>`; чужие заказы недоступны |
| Поставщик обновляет прайс через API | `POST /partner/update`; загрузка файла или URL, проверка результата через `/partner/jobs/<id>` |
| Поставщик включает и выключает прием заказов | `/partner/state`; отключенный магазин скрыт из каталога, оформить его товары нельзя |
| Поставщик видит заказы со своими товарами | `/partner/orders`; ответ содержит только его позиции и их сумму |
| Изменение статуса заказа | API сотрудника и админка; проверены переходы статусов, письмо покупателю и однократный возврат остатка при отмене |

Проверки находятся в `backend/tests/test_auth.py`, `test_catalog.py`, `test_orders.py` и `scripts/smoke_test.py`. Полный сценарий этапа 5 проходит регистрацию, подтверждение email, вход, корзину из нескольких магазинов, адрес, оформление, письма и просмотр созданного заказа.

Основные пути и поля API сохранены по примерам задания. Асинхронный импорт и экспорт возвращают `202` с `job_id`; результат запрашивается отдельно. Смена email через профиль не предусмотрена. Все запросы описаны в [API.md](API.md), готовые примеры находятся в [requests.http](../requests.http).

## Продвинутая часть

В задании она необязательная. Здесь реализованы все перечисленные функции и этапы 6–8.

| Требование | Реализация и проверка |
| --- | --- |
| Экспорт товаров | `/partner/export`; тест проверяет повторный импорт выгруженного YAML без потери цен и характеристик |
| Админка заказов и уведомления при смене статуса | `backend/admin.py`; форма использует тот же обработчик статуса, что и API |
| Отправка email через Celery | `backend/tasks.py`; проверка с отдельным worker, Redis и Mailpit при выключенном eager |
| Импорт и экспорт через Celery | `backend/catalog_tasks.py`; задачи проверены через очередь, результат хранится в `CatalogJob` |
| Форма запуска импорта в админке | Кнопка «Импорт прайса» в списке магазинов; проверяется создание задачи и обработка ошибки очереди |
| Docker Compose и инструкция сборки | `Dockerfile`, `docker-compose.yml`, раздел Docker в README; CI собирает образ, запускает пять сервисов и проверяет заказ через HTTP |

Дополнительно проверяется одновременная покупка последнего остатка двумя покупателями на PostgreSQL. Старые заказы сохраняют свои цены, названия и адрес после изменения прайса или контактов.
