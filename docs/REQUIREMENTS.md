## Принятые решения

- Данные контакта следуют `screens.md`: ФИО, email, телефон и части адреса. Телефон хранится в профиле один раз; адресов не более пяти, как указано в `service.md`.
- Как в исходном API, при создании адреса обязательны город, улица и телефон (его можно взять из профиля). Дом, ФИО и дополнительные части адреса можно пропустить.
- Состояния заказа соответствуют примеру: `basket`, `new`, `confirmed`, `assembled`, `sent`, `delivered`, `canceled`. Изменять состояние может сотрудник, а доступные переходы проверяются.
- Цены хранятся в `DecimalField`: значение `100.50` сохраняется без округления до целого. API передает суммы строками с двумя знаками после точки.
- Заказ хранит снимки цены, названий и адреса. Повторный импорт не должен изменять уже оформленный заказ.
- Корзина не резервирует товар. Остаток проверяется при добавлении и повторно при оформлении; оформление выполняется транзакцией.
- JSON поддерживается дополнительно к формам из исходного Postman. Удаление принимает список ID либо строку с запятыми.
- В локальном режиме Celery выполняет задачи сразу. Отдельные фоновые процессы запускаются в Docker; режим определяется `CELERY_TASK_ALWAYS_EAGER`.
- Демонстрационные данные загружаются отдельной командой, а не при каждом старте приложения.

## Сценарий приемки

1. Установить зависимости, применить миграции, запустить `manage.py check`.
2. Загрузить исходный прайс: в нем 14 товаров и четыре категории. Добавить прайс второго магазина.
3. Зарегистрировать нового пользователя. Убедиться, что до подтверждения email вход закрыт.
4. Подтвердить email, войти, сохранить токен.
5. Отфильтровать каталог и посмотреть подробности одного предложения.
6. Добавить в корзину товары из двух магазинов. Изменить количество, удалить и снова добавить позицию.
7. Создать адрес, оформить заказ, проверить итоговую сумму и уменьшение остатков.
8. Проверить письмо покупателя и накладную администратора.
9. Получить историю и подробности заказа. Повторное оформление того же заказа должно завершиться ошибкой.
10. Проверить, что другой пользователь не получает чужие контакты, корзину и заказы.
11. Проверить заказ от лица каждого поставщика, затем отключить прием заказов одним из магазинов.
12. Изменить статус через админку или API сотрудника, проверить уведомление.
13. Изменить прайс и адрес в профиле; убедиться, что история заказа не изменилась.
14. Экспортировать прайс, проверить выполнение импорта и экспорта через Celery worker.
15. Запустить автоматические проверки из README; изучить результат и покрытие.

Этот документ описывает соответствие и порядок проверки. Он сам по себе не является отчетом об успешном запуске Docker, SMTP или GitHub Actions.
