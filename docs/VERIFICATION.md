# Результаты проверки

Дата проверки: 16 сентября 2026 года.

Среда: Windows, Python 3.14.6, Django 5.2.17, Django REST Framework 3.17.2, Celery 5.6.3.

## Автоматические проверки

| Проверка | Результат |
| --- | --- |
| `manage.py check` | Ошибок нет |
| `manage.py makemigrations --check --dry-run` | Несохраненных изменений моделей нет |
| `python -m pip check` | Конфликтов зависимостей нет |
| `python -m ruff check .` | Ошибок нет |
| Тесты на SQLite | 50 прошли; 1 тест блокировок строк пропущен, поскольку требует PostgreSQL |
| Тесты на PostgreSQL 17.11 | Все 51 тест прошли, без пропусков; 90,174 секунды |
| Покрытие кода приложения | 90% по `coverage report` |
| `python scripts/smoke_test.py` | Полный сценарий через настоящий HTTP-сервер прошел |

Проверены регистрация, подтверждение email, повторная отправка подтверждения после сбоя,
восстановление пароля, отзыв токенов, права пользователей, каталог, импорт и экспорт,
корзина, пять адресов, единый телефон, оформление и отмена заказа, остатки,
история после изменения прайса и адреса, письма и формы Django Admin.

Отдельный тест PostgreSQL запускает двух покупателей одновременно: каждый заказывает
четыре единицы при остатке пять. Только один заказ оформляется, второй получает ошибку,
в базе остается одна единица товара.

Тест Celery запускает настоящий worker в отдельном потоке и передает ему импорт,
экспорт и письмо через очередь `memory://`. Режим немедленного выполнения задач
в этом тесте отключен.

## Проверка работающего сервера

`scripts/smoke_test.py` создает отдельную временную базу, применяет миграции,
загружает демо и запускает Django на свободном локальном порту. Затем через HTTP:

1. Регистрирует покупателя, читает письмо из временной папки и подтверждает email.
2. Выполняет вход и загружает прайс поставщика как файл.
3. Оформляет заказ из двух магазинов, сверяет сумму и накладную.
4. Проверяет ограничения доступа и смену статуса сотрудником.
5. Восстанавливает пароль, проверяет отзыв старого токена, экспорт и выход.

После завершения сервер останавливается, временные файлы удаляются.

Также проверено скачивание исходного прайса с реального адреса GitHub:
четыре категории и 14 товаров. `data/shop1.yaml` совпадает с исходным файлом
по SHA-256: `4ac93f7362c9c36b7a8df3259a6eb98427acde0148c49d0a2d014b8d43506b53`.
В локальной демо-базе два магазина, 14 общих товаров и 16 предложений.

## Границы проверки

- Docker Compose подготовлен, его YAML разобран и конфигурация просмотрена.
  Контейнеры не запускались: Docker на этой машине отсутствует.
- Связка Celery с настоящим Redis и доставка через внешний SMTP-сервис не проверялись.
  Письма проверены через тестовый и файловый почтовые backend; локально настроен вывод в консоль.
- GitHub Actions настроены, но удаленный запуск и публикация требуют репозитория владельца.
- Автотесты проверяют перечисленные сценарии, а не гарантируют отсутствие любых ошибок.

Команды повторной проверки и запуска находятся в [README](../README.md).
